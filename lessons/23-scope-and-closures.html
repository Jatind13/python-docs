Scope and closures

Scope answers one question: when your code uses a name, where does Python look for it? Get this right and two famous errors disappear. Then comes the payoff: closures, functions that remember the variables around them, which is exactly what decorators are built on.

LEGB: the lookup order

Python searches for a name in four places, in this order, and uses the first match:

L: LocalInside the current function
→
E: EnclosingInside any function that wraps this one
→
G: GlobalAt the top level of the file (module)
→
B: Built-inPython's own names: print, len, sum...

If none has it, you get NameError. Note that only functions (and classes, and modules) make a new scope. An if or for block does not: a variable created inside a loop still exists after it.

Reading vs assigning

A function can read a global name freely. But if a function assigns to a name anywhere in its body, Python decides at compile time that the name is local for the whole function. Reading it before the assignment then fails.

Mutating an object is not assigning a name, so this works without any keyword: items.append(x) changes the global list, because the name items is only read.

global and nonlocal

KeywordMeansUse it...
global xAssignments to x in this function change the module-level xRarely. Prefer passing values in and returning them
nonlocal xAssignments to x change the x in the nearest enclosing functionIn closures that keep state, like counters

Why avoid global? Any function can change it at any time, so when the value is wrong you have to read the whole program to find out who changed it. A function that takes inputs and returns outputs can be understood and tested on its own.

Closures: functions that remember

A function defined inside another function can use the outer function's variables. If the outer function returns the inner one, those variables do not disappear when the outer call ends: the inner function carries them along. That function plus its remembered variables is a closure.

The late-binding trap

Closures remember variables, not values. A closure made inside a loop sees the variable's value at the time it is called, which is usually the last one.

add_points crashes with UnboundLocalError. Fix it without global: make it take the current score and return the new one, then use it so the program prints 15.

Hint

Change the signature to add_points(score, points) and call it as score = add_points(score, 10).

Show solution

    return score + points

score = add_points(score, 10)
score = add_points(score, 5)
print(score)

Write make_greeter(greeting) that returns a function. The returned function takes a name and returns "<greeting>, <name>!".

Show solution
def make_greeter(greeting):
    def greet(name):
        return f"{greeting}, {name}!"
    return greet

Write make_accumulator(). It returns a function that adds each number it is given to a private total and returns the total so far.

Show solution
def make_accumulator():
    total = 0
    def add(n):
        nonlocal total
        total += n
        return total
    return add

Recap

  • Names are looked up in LEGB order. Only functions, classes and modules create scopes.
  • Assigning to a name inside a function makes it local for the whole function.
  • global and nonlocal let a function rebind an outer name. Use nonlocal in closures; avoid global.
  • A closure is a returned inner function that keeps its enclosing variables alive.
  • Closures capture variables, not values: watch out inside loops.
