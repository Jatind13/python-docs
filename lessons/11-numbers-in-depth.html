Numbers in depth

Every operator, the order they run in, converting and rounding, comparisons and logic, a few useful modules, and why 0.1 + 0.2 is not 0.3.

Why numbers are Python's strong suit

Python was not built only for math, but numbers are where it shines. Integers never overflow (2 ** 1000 just works), math reads like a formula, and the big scientific libraries (NumPy, pandas, PyTorch) are built on top of it. Getting comfortable with numbers pays off everywhere.

Operators and precedence

OperatorMeaningExample
+ - *Add, subtract, multiply7 * 2 is 14
/Division, always gives a float7 / 2 is 3.5
//Floor division7 // 2 is 3
%Remainder7 % 2 is 1
**Power2 ** 10 is 1024

When an expression mixes operators, Python follows an order (precedence), highest first: ( ), then **, then * / // %, then + -, then comparisons, then not, and, or. When in doubt, add parentheses. They cost nothing and make the intent obvious.

The same operator can also do different jobs for different types. This is called operator overloading: + adds numbers but joins strings and lists, and * repeats them.

Converting, rounding and helpers

int() cuts off the decimals (it never rounds) and float() makes a decimal number. round() rounds, but exact halves go to the nearest even number. The math module adds the rest, and random gives you random numbers.

Comparisons, logic and booleans

Comparisons (< > <= >= == !=) give True or False. Combine them with and, or and not. Booleans are numbers underneath: True is 1 and False is 0, so you can add and count with them. Also, and and or return one of their values, which gives a handy default trick.

Bits and number bases

Bitwise operators work on the binary form of integers: & and, | or, ^ xor, << and >> shift. Note that x << 2 only calculates a value. To change x you must store it back. You can also write numbers in binary, octal and hex, and convert with bin(), oct(), hex().

Why floats look wrong

Computers store decimals in binary, and numbers like 0.1 have no exact binary form, just like 1/3 has no exact decimal form. So tiny errors appear. Do not compare floats with ==. For tolerance use math.isclose(), and for exact decimal math (money) use Decimal created from a string.

Challenges

This prints 14. Change it so it prints 20, by adding parentheses only.

Show solution
print((2 + 3) * 4)

With floats, 0.1 + 0.2 == 0.3 is False. Use Decimal to print True for the same sum.

Show solution
from decimal import Decimal
print(Decimal("0.1") + Decimal("0.2") == Decimal("0.3"))

For n = -7.5, print math.floor(n) and then math.trunc(n), each on its own line.

Show solution
import math
n = -7.5
print(math.floor(n))
print(math.trunc(n))

Recap

  • Operators: + - * / // % **. Use parentheses whenever the order is not obvious.
  • int() cuts, round() rounds halves to even, floor goes down, trunc drops decimals.
  • and, or and not combine conditions. True is 1 and False is 0.
  • Floats are approximate. Use math.isclose to compare and Decimal("...") for exact decimals.
