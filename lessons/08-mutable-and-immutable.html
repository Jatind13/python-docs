Data and memory

Mutable and immutable

Which objects can change in place and which cannot, and why Python made numbers and strings behave differently from lists.

10 min3 challenges3-question quiz

The idea

Every Python object is either mutable (it can change in place) or immutable (it never changes). With an immutable object, "changing" it really means creating a new object and moving the name to it.

A simple test: change the object, then compare id() before and after. Same id means it changed in place.

MutableImmutable
list, dict, setint, float, bool, str, tuple, frozenset, None

Lists: mutable

A list changes in place: append, item assignment and similar methods all work on the same object.

Gotcha: methods that change a list in place return None. nums.sort() sorts the list and returns None, so x = nums.sort() leaves x empty-handed. Use sorted(nums) when you want a new sorted list.

Tuples: immutable

A tuple is like a list that is locked. You can read from it, but you cannot assign to an item.

To "change" a tuple, build a new one: point = (10, point[1]). One subtlety: a tuple is locked in which objects it holds, but those objects can still be mutable.

Numbers and strings: immutable

Numbers and strings never change either. Every operation builds a new object.

Numbers and strings are different kinds of value. A number is a single value. A string is a sequence of characters, so you can index and slice it (s[0]), but you cannot assign to a position.

Why numbers and strings are immutable

  • Safe to share. Many names can point at the same 5 or "hi", and nobody can change it behind your back. The aliasing surprise from the Variables page cannot happen.
  • They can be dictionary keys. A key must never change, or Python could not find it again. Only immutable (hashable) objects can be keys or set members.
  • Memory reuse. Because they never change, Python can reuse one object for equal small numbers and short strings. This is an implementation detail: always compare values with ==, not is.
  • Predictable. Whatever you pass a number or string to cannot alter the original.

Lists are mutable because they are meant to be built up and changed. Copying a whole list on every change would be slow. That is the trade-off: lists are flexible, numbers and strings are safe.

Recap

  • Mutable (list, dict, set) changes in place. Immutable (int, float, bool, str, tuple) never does: Python builds a new object.
  • Same id() after a change means it was changed in place.
  • A tuple locks which objects it holds, not whether they can change.
  • Immutable objects are safe to share, can be dictionary keys, and let Python reuse memory.
