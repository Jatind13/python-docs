Memory and garbage collection

How values live in memory, what a reference count is, and how Python cleans up objects you no longer use, without you doing anything.

10 min3 challenges3-question quiz

Everything is an object

Every value you create, whether a number, a string, a list or a dictionary, is an object stored in memory. Each object has three things:

  • Identity: a unique id, shown by id(). It never changes during the object's life.
  • Type: what kind of object it is, from type().
  • Value: its content. For mutable objects this can change, for immutable ones it cannot.

Variable names are only references: labels that point to objects. Containers such as lists, tuples, dicts and sets also hold references to their items, not copies of them. That one idea explains most of Python's behaviour, including the aliasing you saw earlier.

Reference counting

Each object keeps a count of how many references point at it. Assigning a name, putting it in a list, or passing it around adds a reference. Deleting a name or reassigning it removes one. When the count reaches zero, nobody can reach the object any more, so Python frees its memory immediately.

Watch it happen. Use the three examples: plain names, a list holding references, and a cycle.

See a reference count yourself

sys.getrefcount(x) returns the count. It always shows one more than you expect, because passing x to the function creates a temporary reference.

del y removes the name y. It does not delete the object. The object is only freed when its count reaches zero.

Garbage collection

"Garbage collection" is automatic memory cleanup. CPython does it in two layers:

  1. Reference counting frees most objects the instant their count hits zero. This is why memory is usually released right away.
  2. The cyclic garbage collector handles the one case counting cannot: objects that refer to each other. In a cycle, every object keeps the other's count above zero, so none reaches zero. The collector periodically looks for groups of objects that can only be reached from each other and frees them.

You almost never need to call gc.collect() yourself. What matters in practice:

  • You do not free memory manually in Python. Let names go out of scope or reassign them.
  • Memory problems usually come from references you forgot about, such as a global list that keeps growing or a cache that never empties. Anything still referenced is never freed.
  • For large data, drop references you no longer need (del big or reassign it) so memory can be released.

Recap

  • Every value is an object with an identity, a type and a value. Names and containers hold references to objects.
  • Each object has a reference count. At zero, Python frees it immediately.
  • del x removes a name, not necessarily the object.
  • The cyclic garbage collector frees objects that only refer to each other. You rarely call it yourself.
  • Memory issues usually come from forgotten references, not from missing frees.
