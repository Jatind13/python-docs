Control flow

break, continue, pass and exit

Four keywords and calls that change how a program flows: leave a loop, skip a round, do nothing on purpose, or stop everything. Plus how indentation decides what each one affects.

The four at a glance

KeywordWhat it doesWhere it works
breakLeaves the loop immediately. Code after the loop carries on.Inside a loop only
continueSkips the rest of this round and jumps to the next one.Inside a loop only
passDoes nothing. A placeholder where a block is required but you have nothing to write yet.Anywhere
exit() / sys.exit()Stops the whole program, not just a loop.Anywhere

break: leave the loop

Use break when you have found what you were looking for, or when continuing makes no sense. The loop ends on the spot, and the line after the loop runs next.

continue: skip to the next round

continue abandons the current round and starts the next one. The loop itself keeps going.

break vs continue in one line: break ends the loop, continue ends only the current round. Code written after continue in the same block never runs for that round.

How indentation decides what they affect

Both keywords act on the nearest loop around them, and indentation tells Python where that is. Two rules to remember:

  • Where the keyword sits decides when it fires. Indented under an if, it fires only when that condition is true. Indented at the loop level, it fires every round.
  • In nested loops, they affect only the inner loop that contains them. The outer loop carries on.

Loop else

Python lets a loop have an else. It runs only if the loop finished without hitting break. It is neat for "search, and say so if not found".

pass and exit

pass keeps a block valid when you have nothing to put in it yet. An empty block is an IndentationError, so write pass as a stand-in:

if user_is_admin:
    pass          # TODO: add admin features later

sys.exit() ends the whole program immediately, even from inside a loop or nested blocks. In scripts use sys.exit(). The plain exit() and quit() are intended for the interactive prompt. Here the page simply stops the program quietly.

A common pattern is while True: with a break inside: loop forever until a condition is met. It is safe only because the break exists.

Challenges

Print the first negative number in the list (-2), then stop looking. Keep the first line as it is: the checker tries other lists.

Show solution
nums = [4, 9, -2, 7, -5]
for n in nums:
    if n < 0:
        print(n)
        break

Print the numbers 1 to 10, one per line, but skip every multiple of 3. Use continue.

Show solution
for n in range(1, 11):
    if n % 3 == 0:
        continue
    print(n)

Make the program stop completely after it prints 3, so end of program is never printed. (A break would not be enough.)

Show solution
import sys
for n in range(1, 10):
    print(n)
    if n == 3:
        sys.exit()
print("end of program")

Recap

  • break leaves the loop, continue skips to the next round, pass does nothing, sys.exit() stops the program.
  • break and continue only work inside loops, and they affect the nearest enclosing loop.
  • Indentation decides when they fire: under an if only when it is true, at loop level every round.
  • A loop else runs only when the loop was not ended by break.
