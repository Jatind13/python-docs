Object-oriented Python

Inheritance and the rest of OOP

The four ideas OOP is known for, in Python terms: inheritance (reuse a class), polymorphism (one call, many behaviours), encapsulation (protect an object's data) and abstraction (hide the details behind a simple interface). Plus the three decorators every class-writer uses.

Inheritance: build on an existing class

class Child(Parent): gives the child every attribute and method of the parent. The child can add new ones and override (replace) existing ones. Use it for an "is a" relationship: a MasalaChai is a Chai.

super() means "the next class up the chain". Call super().__init__(...) in a child's __init__, or the parent's setup never runs and its attributes are missing. You can call any parent method this way: super().describe().

Polymorphism: same call, different behaviour

Different classes can offer the same method name. Code that calls that method does not need to know which class it has. Python does not even require a shared parent: if it has the method, it works. This is called duck typing: "if it walks like a duck and quacks like a duck...".

Encapsulation: protecting data

Python has no truly private attributes. It uses naming conventions instead, and trusts developers to respect them:

NameMeaning
balancePublic: part of the interface, use freely
_balanceInternal: "please do not touch from outside". Only a convention
__balanceName-mangled: Python renames it to _ClassName__balance, so subclasses cannot clash with it by accident. Still reachable, just awkward

@property: attributes with rules

A property looks like a plain attribute from outside, but runs a method when read or set. Start with public attributes; switch to a property later when you need validation or a computed value, and no calling code has to change.

KindFirst parameterTypical use

Abstraction and multiple inheritance, briefly

Abstraction means the caller uses a simple interface and does not care how it works inside. An abstract base class enforces that every subclass provides the interface:

A class can also inherit from several parents: class C(A, B):. Python then searches for methods in the MRO (method resolution order): the class itself, then A, then B, then object. Use it sparingly, mostly for small add-on "mixin" classes.

Composition over inheritance. If the relationship is "has a" rather than "is a" (a Car has an Engine), store the other object as an attribute instead of inheriting from it. Deep inheritance trees are hard to change.

Challenges

Make Dog and Cat subclasses of Animal. Each overrides sound() to return "Woof" and "Meow". The inherited speak() should then print lines like Bruno says Woof.

Show solution
class Animal:
    def __init__(self, name):
        self.name = name
    def sound(self):
        return "..."
    def speak(self):
        return f"{self.name} says {self.sound()}"

class Dog(Animal):
    def sound(self):
        return "Woof"

class Cat(Animal):
    def sound(self):
        return "Meow"

for pet in [Dog("Bruno"), Cat("Mittens")]:
    print(pet.speak())

Write Manager(name, salary, team_size) that inherits from Employee, uses super().__init__ for name and salary, stores team_size, and overrides annual_bonus() to return the parent's bonus plus 1000 per team member.

Show solution
class Employee:
    def __init__(self, name, salary):
        self.name = name
        self.salary = salary
    def annual_bonus(self):
        return self.salary * 0.10

class Manager(Employee):
    def __init__(self, name, salary, team_size):
        super().__init__(name, salary)
        self.team_size = team_size

    def annual_bonus(self):
        return super().annual_bonus() + 1000 * self.team_size

m = Manager("Asha", 100000, 5)
print(m.name, m.annual_bonus())

Give Thermostat a celsius property whose setter raises ValueError below -273.15, and a read-only fahrenheit property (celsius * 9 / 5 + 32).

Show solution
class Thermostat:
    def __init__(self, celsius):
        self.celsius = celsius

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("below absolute zero")
        self._celsius = value

    @property
    def fahrenheit(self):
        return self._celsius * 9 / 5 + 32

Recap

  • class Child(Parent): inherits everything; override what differs; call the parent with super().
  • Polymorphism: different classes, same method name. Python only cares that the method exists.
  • _name means internal; __name is name-mangled. Neither is truly private.
  • @property adds validation or computed values behind plain attribute syntax.
  • @classmethod gets the class (alternative constructors); @staticmethod gets nothing.
  • Abstract base classes enforce an interface; the MRO decides lookup in multiple inheritance.
